Overlay & geometry

7 tools analysis_overlay_tools

The classic vector operations. Every distance and area is computed in a projected UTM CRS estimated from the data — units='degrees' is refused, and Web Mercator input is re-measured, because a 10 km buffer in EPSG:3857 at 40°N would cover only ~7.7 km on the ground.

Spatial statistics

7 tools analysis_spatial_stats_tools → libpysal / esda / spreg / pygeoda

The questions a choropleth provokes: is this pattern real or could randomness look like it, which areas are the hot spots, does X still explain Y once neighbours resemble each other. Everything rests on a spatial weights matrix, and two traps are handled centrally — rows with a missing value are dropped before the weights are built (dropping after leaves the matrix indexed to rows that are gone, silently pairing each area with the wrong neighbours), and areas with no neighbours are reported as islands rather than passed off as “not significant”. GeoDa is a desktop GUI with no scripting interface, so its algorithms arrive through pygeoda, its own C++ core.

global_spatial_autocorrelation

Moran’s I, Geary’s C and Getis-Ord G with permutation p-values — is the variable clustered at all? Reports each against its expectation under spatial randomness, and reads the inverted Geary convention correctly.

File
local_moran_lisa

GeoDa’s LISA cluster map: every area classed High-High, Low-Low, or a High-Low / Low-High spatial outlier. Lands as a categorical layer with its own legend, not a ramp.

MapFile
local_getis_ord

Gi* hot-spot / cold-spot map banded by confidence (99% / 95%) — the ArcGIS-style hotspot analysis, for when clusters of high or low matter but outliers do not.

MapFile
spatial_regression

OLS with Lagrange Multiplier diagnostics, refitting as a spatial lag or spatial error model by the standard specification rule — and it says which it chose and why. Residuals come back as a map, because leftover structure there is the honest check.

MapFile
regionalize

SKATER, REDCAP, AZP, SCHC and max-p: group areas into regions that are similar on several variables and contiguous on the map. Unlike k-means, no region comes out scattered.

MapFile
moran_scatterplot

GeoDa’s signature plot: each area against its neighbours’ average, coloured by quadrant, the fitted slope being Moran’s I itself.

File
spatial_weights

Queen, rook, k-nearest, distance band or kernel — with neighbour counts, islands and sparsity, plus a GeoDa-readable .gal/.gwt. The first thing to check when a LISA result looks wrong.

Satellite embeddings

13 tools rs_embed_tools → rs-embed service

Remote-sensing foundation models over a region you draw, a region you name, or every polygon in a layer. Colours in an embedding visual are a three-component PCA — they show what looks alike, they are not land-cover classes, and they are not comparable between separate runs. Models split two ways that matter before you pick one: copernicus, gse and tessera are precomputed and return in seconds; the other seventeen are computed on the fly, and each takes either a single image or a timeseries.

add_raster_layer

Drape a georeferenced image the agent produced itself — a clustering, a difference surface, anything computed in execute_code — over its extent. Without it, pixels computed outside the embedding tools had no way onto the map.

Map
embed_region

Embed a region with one or more models and put the result on the map as a raster layer, plus the vectors to download.

MapFile
embed_zones

One embedding vector per polygon for a whole layer — census tracts, catchments, parcels — keyed by an id column, optionally clustered into look-alike groups and mapped as categories. This is the many-polygon counterpart to embed_region; a date range narrows the imagery for on-the-fly models. Tile budget is finite, so it reports how many zones actually received pixels rather than silently embedding a subset.

MapFile
fit_zone_model

Fit a model on zone embeddings against a column you supply — the supervised step after embed_zones, for when no pretrained head fits your target.

File
segment_region

Unsupervised segmentation into k look-alike zones from the embedding — land-cover-style, without labels.

MapFile
embedding_change

How much a region changed year over year, measured in embedding space rather than raw pixels.

MapFile
predict_for_region

Run a pretrained downstream head on an embedding to predict a value — the "use the embedding" step, starting from a region rather than a saved package.

MapFile
align_embedding_colors

Re-colour several already-embedded regions on ONE shared PCA basis, so similar colour means similar ground across the layers. Each embedding is otherwise fitted and stretched on its own, which makes two maps individually meaningful and mutually incomparable. Same model only — two models’ embeddings are different spaces. Reuses embeddings already paid for.

MapFile

Cosine similarity between two regions: 1.0 means indistinguishable from space.

8 tools langchain_geo_tools · admin_boundary_tools · langchain_geocode_tools

admin_boundary

A boundary from a name, with no upload: state, county, incorporated place or CDP, straight onto the map and already shaped for embed_zones. subdivide="tracts" returns the census tracts inside a named county. Knowledge-base functions & static renders

4 tools geo_analysis_tools

A second route into analysis: instead of a curated tool, run a spatial function that was extracted from a knowledge-base notebook, chaining steps by passing one step’s file_id into the next. The two renderers here are deliberate fallbacks — a robust plot for when an extracted notebook’s own plotting code fails on the installed matplotlib.

kb_run_geofunction

Execute a named spatial function from a knowledge-base block by doc_id + function_name, passing (Geo)DataFrames as file ids. Returns a file id, so steps chain: load data → join and count → render.

File
kb_select_rows

Filter a (Geo)DataFrame file to rows whose column matches a value set — violent crime types out of all crime types — returning a new file id for the next step.

File

A hexbin point-density PNG from a points file. This is the “heat map” render, distinct from a choropleth — and distinct from add_map_layer’s live density surface, which is what you want if the result should be explorable.

What it does not do

  • No raster analysis. There is no zonal statistics, band math, reclassify, terrain slope or aspect over a GeoTIFF. The route today is execute_code with rasterio, or a GDAL algorithm through qgis_processing_run. The map client also models vector layers only, so a raster result other than a satellite embedding arrives as a PNG.
  • No network or routing analysis — no shortest path, service areas or travel-time isochrones.
  • Spatial statistics stops short of a few things. No geographically weighted regression (GWR/MGWR), no spatial panel or discrete-choice models, and join counts, quantile LISA and local Geary have no curated tool. The PySAL stack and pygeoda are installed in the sandbox too, so those run through execute_code — but without the automatic map layer the curated tools deliver.
  • An embedding package is the reusable artifact. embed_region saves the real vectors (grid__<model> per pixel, pooled__<model> for the region), and list_embedding_packages → predict_from_package or align_embedding_colors reuse one without paying the imagery provider again. Anything the curated tools do not cover — a different k, another metric, more than two periods — is written against that package in execute_code and delivered by add_map_layer (polygonized, for a legend and clickable zones) or add_raster_layer (the pixel array saved as an image — a matplotlib figure misregisters the layer, because its axes and margins become part of it). The exported grid above 90,000 cells is decimated, and the package states its grid_stride.
  • Prediction coverage is narrow. One task (corn_presence, Illinois CDL 2022) for three models — gse, satmae, dofa — out of twenty embedding models, and the best of the three scores 0.667 accuracy on n=30. Quote the validation score: a confident number from a weak head is still a weak number.
  • Prerequisites are real, but a region no longer has to be drawn. Most analysis tools load only once files are attached to the conversation — though not all: the satellite-embedding tools, admin_boundary, geocode_places, add_map_layer and list_conversation_files are available with nothing attached, because each can start from a place name, a drawn region, or geometry the agent already holds. Among the upload-gated ones, if every attached file is a spreadsheet (.csv, .tsv, .xlsx), the four tools that need a vector file (inspect_vector, vector_to_geojson, reproject_vector, vector_spatial_join) are withheld rather than offered and left to fail. Everything else, including buffering and gridding a point CSV, stays available. The embedding tools need a geometry, and there are now two ways to give them one: right-drag the map to draw a region, or name a US state, county or city and let admin_boundary fetch the official boundary.
  • Files belong to the conversation that made them. Ask list_conversation_files for what a conversation has produced — it reads the store, which is the record; the transcript is not, because earlier links get trimmed from context. Saved embedding packages are the deliberate exception: those predate per-conversation files and stay reusable from anywhere, so list_embedding_packages shows deployment-wide results and a package should be matched on its region and months, not on its name. File downloads are not yet authenticated.
  • Verified unevenly. The heatmap, grid aggregation, attribute selection, buffer and satellite embedding paths have been driven end to end in a browser, as have the LISA, Gi* and regionalization maps, confirmed against planted hot and cold spots that the statistics had to recover in the right places. The named-area path is browser-verified too — admin_boundary to embed_zones to a categorical map layer, for a city and for the 48 census tracts of a county. The rest rest on unit tests.
