# GeoParquet. REQUIRED although nothing imports it by name: pandas and geopandas load it on

# (agent_runtime/langchain_geo_tools.py); read_vector, the temporal tools and
# extractors/geo_handles.py read it back. Never declared until 2026-10-01: in the deployed
# image every reproject_vector call failed with "Missing optional dependency
# 'pyarrow.parquet'", while dev machines, which have it, passed. Pinned to the sandbox
# image's version, which reads the same files.

# Extraction readers. Each is imported lazily by an extractor that degrades instead of failing
# when it is missing, which is why the absence went unnoticed: publication_extractor reads every
# .pdf as empty text without pypdf and every .docx as empty without python-docx, data_extractor
# cannot open NetCDF/HDF/GRIB without xarray, and notebook_extractor falls back to a regex that
# cannot parse `obj?` or a `!command` inside a block, where IPython's own transformer can. Dev
# machines had all four; the image had none. xarray brings only its scipy engine, so NetCDF3
# opens and NetCDF4/HDF5 still does not: that needs netCDF4 or h5netcdf, which neither dev nor
